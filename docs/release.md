## v2.60.0 — Page Checksum Errors and Object Store Prefetch

*Released: 2026-10-18*

### Core Features

- Add `checksum-page-error` option to error on invalid page checksums. This option applies to the `backup`, `restore`, and `expire` commands. The `backup` command defaults to a warning for each file (as before) and now also reports the total number of checksum warnings at the end of the backup. The `restore` and `expire` commands default to an error. Previously the `restore` command did not report invalid page checksums at all. 

- Support for GCS Workload Identity Federation. Set `repo-gcs-key-type=web-id` and set `repo-gcs-key` to an external account credential file, e.g. as generated by `gcloud iam workload-identity-pools create-cred-config`. The web identity token is exchanged for an access token without a service account key. The token file is reloaded on each exchange to pick up rotated tokens, e.g. Kubernetes projected service account tokens. Service account impersonation is not supported. 

- Prefetch multi-file/range reads from object stores. Requests are queued ahead of the current read so requests proceed while reading, and small gaps between files are read over instead of starting a new request. `Restore` uses this to read bundled files and block incremental maps, and `backup` uses it to read block incremental maps from the prior backup. `repo-storage-prefetch` (default 3) sets how many requests are queued and `repo-storage-read-over` (default 64KiB) sets the largest gap that is read over. 

### Core Improvements

- Reduce keep-alive requests to remote processes. A keep-alive was sent to every remote each time a job completed in `archive-push` and `backup`, even when the remotes had just been sent a request. A keep-alive is now sent only when no request has been sent to the remote for 30 seconds. 

- Retry Azure batch sub-requests missing from the response. When Azure fails a batch delete it may return a single response for the entire batch. The sub-requests with no response were treated as complete, so only one file per batch was removed while the command reported success. Sub-requests with no response are now retried. 

- Reduce the manifest checks made when reconstructing `backup.info`. The `backup`, `expire`, and `annotate` commands no longer check for a `backup.manifest` when the repository listing shows the backup path does not exist, or when a diff or incr backup belongs to a full backup set that is not in `backup.info`. Each check is a request so on an object store the check for a missing manifest is logged as a 404. 

- Use original size to determine if a file should be bundled. The size of a block incremental file in the prior backup was used to decide whether to bundle it, so a file that had grown past `repo-bundle-limit` could still be stored in a bundle. The current size of the file is now used. 

- Add context to block map read errors during backup. An error reading the block map of a prior backup now reports the file, repository path, offset, and map size. A read that returns fewer bytes than expected is reported as such instead of as a parse error. 

- Cast `current_timestamp` to `text` in the backup start label. A user-defined implicit cast from `timestamptz` to `text` caused the backup to fail with "operator is not unique: unknown || timestamp with time zone". The label text is unchanged. 

- Support building on illumos. An OmniOS job has been added to CI. Solaris may also work but has not been tested. 

- Support OpenSSL 4. Building against OpenSSL 4 failed because `X509_get_subject_name()` now returns a `const` name. 

- Fix clang builds. On Linux, gcc installs `libbacktrace.a` where clang also looks for it but installs `backtrace.h` where only gcc can find it. A clang build found the library and then failed to compile. The library is now only used when its header is found. Return types that clang reports as narrowing conversions in debug builds are also fixed. 

- Migrate code generation from C to Python. Code is generated during the build from the option, error, help, and PostgreSQL declarations by a Python tool instead of a C tool that had to be built first. Building from a git checkout requires PyYAML instead of libyaml. The release tarball includes the generated code and requires neither.

## v2.59.3 — Weak Encryption Subkey Bug

*Released: 2026-10-04*

### Core Bug Fixes

- Fix possible checksum error loading encrypted info and manifest files. A large encrypted info or manifest file could lose its last lines when loaded, which failed the checksum. The lost lines had to fit in the final cipher block, so this is unlikely in practice. 

- Fix possible weak encryption subkeys/salts. When OpenSSL could not get random data from the operating system the failure was ignored, and subkeys and salts were generated from memory that was not random. An error is now reported. 

## v2.59.2 — PostgreSQL 19beta4 Support

*Released: 2026-09-27*

### Core Bug Fixes

- Fix empty block map when file is truncated to zero during backup. A block incremental file larger than `repo-bundle-limit` and truncated to zero by PostgreSQL during a backup was stored as a block map with no blocks. Every later backup that referenced the file failed with "unexpected eof" until the next full backup. 

- Disable read retry when filters are passed to the driver. A retried read from a repository on an object store, accessed through a repository host, crashed. These reads are no longer retried by the client. The repository host still retries its read from the object store. 

- Fix pagination of S3 version listing. Reading a repository at a target time with `repo-target-time` failed with "unable to find child 'NextContinuationToken'" when more than a thousand versions were listed under a prefix. 

- Set the Azure version header for `SAS` authentication. Batch deletes require the version header, so with `SAS` authentication every batch was rejected. The rejection looked like a single failed file, and the rest of each batch was not deleted while `expire` reported success, leaving expired backups and WAL in the repository. 

- Fix async `archive-push` stalling on a zero-size backup history file. A zero-size backup history file, e.g. in a cluster copied from a storage snapshot, failed every asynchronous `archive-push` run, so no WAL was archived. `archive-push-batch-size` is now converted to a segment count using the size of the first ready WAL segment. 

- Fix `annotate` command on a remote encrypted repository. When the repository was encrypted and the cipher was configured only on the repository host, `annotate` failed to load `backup.info`. 

### Core Features

- PostgreSQL 19beta4/rc1 support. PostgreSQL 19beta4 reverted online page checksum changes, so the page checksum version is again limited to 0 and 1. It also changed the `pg_control` version and the WAL page magic number. 

## v2.59.1 — PostgreSQL 19beta3 Support

*Released: 2026-08-17*

### Core Bug Fixes

- Fix hang when the chunk buffer is smaller than the input buffer. A multi-part upload to S3, GCS, or Azure could loop forever when the chunk buffer was smaller than the input buffer, e.g. after the chunk size grew during the upload. The chunk buffer is now always large enough to hold the input buffer. 

- Compare a new backup label only against its own full backup set. Some object stores keep listing a prefix after everything under it has been deleted, e.g. MinIO with object locking or SeaweedFS, so a full backup that was removed could still appear in the repository. Every diff and incr backup after it then failed with "new backup label ... is not later than latest backup label ...". A new label is now compared only against the backups in its own full backup set. 

- Fix source archives generated by GitHub missing files required to build. The source archives GitHub generates for a release were missing the code generation tooling and the files it reads, so they could not be built. Only the distribution tarball is trimmed now. 

### Core Features

- PostgreSQL 19beta3 support. PostgreSQL 19beta3 changed the WAL page magic number. 

### Documentation Improvements

- Document exception for dots in S3 bucket names when `repo-s3-uri-style=path`. With `repo-s3-uri-style=path` the bucket is part of the path instead of the host name, so dots in the bucket name do not cause a certificate host name mismatch. 

- Remove explicit `hot_standby` configuration from user guide. `hot_standby` has been enabled by default since PostgreSQL 10. The quickstart now notes that a standby does not accept read-only connections without it. 

### Documentation Development

- Fix broken release link in news.xml. 

## v2.59.0 — PostgreSQL 19beta2 Support

*Released: 2026-07-20*

### Core Bug Fixes

- Fix `expire` removing a backup in progress on another host. A backup is not added to `backup.info` until it completes, so when `expire` ran on one host while a backup was running on another, e.g. `expire` on a standby while the primary is backed up, the backup in progress was removed. Expiration no longer removes the latest backup when it is in progress or resumable. 

- Fix `archive-push-queue-max` not enforced when a WAL file errors. In asynchronous mode the queue was measured against the WAL yet to be pushed. When a WAL file errored repeatedly the WAL files after it were pushed and no longer counted, although they stayed in `pg_wal`, so the queue limit was never reached and `pg_wal` could fill the disk. The queue is now measured against all the WAL PostgreSQL is waiting to archive, as in synchronous mode. 

- Fix async `archive-get` failure during recovery across a timeline switch. Two async processes could race for the archive lock, and the one that lost exited before fetching the segment it was started for. The `archive-get` that started it then waited for `archive-timeout` and returned an error for a segment that exists, which could end recovery early, especially across a timeline switch. The segment is now fetched directly when the async process that should fetch it is not running. 

- Fix potential buffer overrun in error module. A stack trace too long for its buffer was not terminated and could be read past the end of the buffer, and an error message too long for its buffer could write past the end of it when a system error was appended. Both require an unusually long message. 

- Fix use-after-free of parallel protocol client. A client that ran out of work was freed but left in the client list and freed again on a later call. With debug or trace logging this read freed memory and could crash, e.g. a parallel backup with `log-level-file=trace`. 

- Fix heap overflow when a pg option is set without pg1. When `pg` options were set for other indexes without `pg1-path`, e.g. `pg2-path` and `pg3-path`, the index map was overwritten. This corrupted the heap on musl, e.g. Alpine, and caused a segmentation fault. The highest numbered `pg-path` was also dropped. 

- Fix crash when a signal arrives during exit on musl 1.2.6. musl 1.2.6, e.g. on Alpine 3.24, crashes when `exit()` is called while an exit is already in progress. This happened when a signal arrived during exit, e.g. when the `server` command terminated a child process that was already exiting. A signal that arrives during exit is now ignored. 

### Core Features

- PostgreSQL 19beta1/beta2 support. Adds support for PostgreSQL 19beta1/beta2. PostgreSQL 19 can enable and disable page checksums online, and page checksums are not validated while either is in progress. 

- Add `archive-expire-before` option to clean up WAL archive. The `expire` option `archive-expire-before` removes WAL before a given segment from the archive but never WAL that a retained backup requires. It can clean up the archive from the restartpoint of a standby with `archive_cleanup_command` instead of `pg_archivecleanup`, which does not know about retention. 

- Add batch delete for Azure storage. Files are removed with the Azure Blob Batch API, up to 256 per request, instead of one request per file. This speeds up `expire` and other commands that remove files from the repository. 

- Add support for S3 Outposts. Set `repo-s3-service=s3-outposts` when using an S3 Outposts endpoint. The option sets the service name used for request signing and defaults to `s3`. 

- Add S3 process authentication. Set `repo-s3-key-type=process` and set `repo-s3-process-cmd` to a command that outputs temporary credentials in the JSON format of the AWS process credential provider. The credentials are refreshed before they expire. 

- Provide a distribution tarball with generated code and documentation. The tarball includes the generated code and the rendered man page and HTML documentation, so it builds and installs without the code generation and documentation tooling, including `libyaml`. 

### Core Improvements

- Reconnect SFTP storage after the server drops an idle connection. SFTP servers and firewalls may drop a connection that has been idle for a while, e.g. the repository read connection during the copy phase of a backup, and the next use failed with a socket error. A dropped connection is now reopened and the operation is retried once. 

- Add user/group caching for faster manifest build. When user and group names are looked up through a remote name service, e.g. sssd or LDAP, each lookup is a round trip, which dominated the manifest build for clusters with millions of files. User and group names are now cached. 

- Add per-repo backup progress to `info` command output. When backups run on more than one repository at once, the `info` command now reports progress for each repository as well as overall progress. The JSON output has a `repo` array for each backup lock. 

- Add `backup.info` checks to `verify` command. The `verify` command now warns when a backup in the repository is not in `backup.info` and when a backup in `backup.info` is missing from the repository. A missing backup is reported as having a missing manifest. 

- Allow the S3 STS endpoint to be configured. Set `repo-s3-sts-host` to use a regional STS endpoint with `repo-s3-key-type=web-id`, e.g. `sts.eu-central-2.amazonaws.com`. AWS opt-in regions do not accept credentials from the global endpoint, which is still the default. 

- Add `archive-push-batch-size` to limit WAL pushed per asynchronous run. In asynchronous mode `archive-push-queue-max` is only checked at the start of a run, so a run working through a large backlog could let the queue grow well past the limit. `archive-push-batch-size` (default 16GiB) limits the WAL pushed per run, so the queue is checked again sooner. 

- Exit async `archive-push` on first error. When the repository was unavailable the async process kept trying every ready WAL segment, so a run could take long enough for `pg_wal` to fill before `archive-push-queue-max` was checked again. The run now exits on the first error, after the jobs in progress finish. 

- Harden HTTP chunked response parsing. Chunk extensions and trailers are now accepted, `transfer-encoding` is compared without regard to case, and a response with both `transfer-encoding` and `content-length` is rejected. 

- Error when running as root unless `allow-root` is enabled. Running a command other than `restore` as root could create files in the repository, e.g. `backup.info`, that the PostgreSQL user cannot access. `allow-root` is disabled by default for every command except `restore`, and the check also applies on remote hosts. 

- Fewer binary searches when building manifest. The manifest build for a diff or incr backup searched the prior manifest three times for each file. It now searches once, which saves millions of searches for clusters with millions of files. 

- Improve seek performance during block incremental delta restore. A seek and a flush of the write buffer were done for every block written during a block incremental delta restore, and blocks are often 8KiB. The file position is now tracked and the seek and flush are only done when needed. 

- Bundle backup files in order rather than scanning for a better fit. A file that would push a bundle over `repo-bundle-size` was skipped for a smaller file later in the queue. Files are now added in order and a bundle is closed once it reaches `repo-bundle-size`, so a bundle may exceed it by up to `repo-bundle-limit`. 

- Report the underlying error when a query fails to complete. When the connection was lost after the first result of a query was delivered, e.g. under load, the error was the generic "NULL result required to complete request". The error from PostgreSQL is now reported, with hints about a lost connection and about aggressive `idle_session_timeout` and `idle_in_transaction_session_timeout` settings. 

- Report the actual error when an S3 credential request fails. An error from AWS for a `web-id` or `pod-id` credential request was reported as a failure to parse the response. The error returned by AWS is now reported, and the tokens are redacted when the request is logged. 

- Report `archive-push` spool path errors to the PostgreSQL log. When the async spool path could not be created, e.g. permission was denied, the error could not be written to the spool and `archive-push` failed with a generic timeout that pointed at the async log. The spool path is now created before the async process starts, so the error appears in the PostgreSQL log. 

- Hint that pgBackRest may be out of date when a version is unsupported. When pgBackRest does not recognize a PostgreSQL version, e.g. an older pgBackRest on the restore host reading a backup of a newer cluster, the error now hints that pgBackRest may need to be updated on all hosts. The version is reported in user-facing form, e.g. 13 rather than 130000. 

- Add systemd notify integration. When built with `libsystemd`, the `server` command notifies systemd when it is ready to accept connections and when it is stopping, as PostgreSQL and PgBouncer do. 

- Suppress `unused parameter` errors in meson compiler probes. The meson compiler probes declared `main()` parameters they did not use, which failed the probes when unused parameter warnings were errors. 

- C11 is now the minimum C standard.

## v2.58.0 — Object Storage Improvements

*Released: 2026-01-19*

### Core Bug Fixes

- Fix deadlock due to logging in signal handler. A signal that arrived while a lock was held by `gmtime_r()`, e.g. the SIGTERM sent by `stop` with `--force`, could deadlock when the signal handler logged. The signal handler now logs with only async-signal-safe functions. 

### Core Features

- HTTP support for S3, GCS, and Azure. An object store endpoint can now begin with `http://` to connect without TLS. HTTPS is still used when the endpoint does not specify a protocol. 

- Allow expiration of oldest full backup regardless of current retention. The `expire` option `--oldest` expires the oldest full backup and the backups that depend on it regardless of the retention settings, e.g. when the repository is running out of space. WAL before the oldest remaining full backup is expired as well. 

- Support for Azure managed identities. Set `repo-azure-key-type=auto` to fetch credentials automatically using managed identities instead of configuring them. The credentials are refreshed before they expire. 

- ***Experimental*** support for S3 EKS pod identity. Set `repo-s3-key-type=pod-id` to fetch credentials automatically using EKS pod identity instead of configuring them. The credentials are refreshed before they expire. 

- Allow configuration of TLS cipher suites. Set `tls-cipher-12` for TLS 1.2 and `tls-cipher-13` for TLS 1.3, e.g. for compliance. The cipher suites apply to every connection a process makes. 

- Allow process priority to be set. `priority` sets the scheduling priority of pgBackRest processes from -20 to 19, as with `nice`. A higher value makes pgBackRest less likely to interfere with PostgreSQL. 

### Core Improvements

- Allow dots in S3 bucket names when using path-style URIs. Dots in a bucket name only cause a certificate host name mismatch with host-style URIs, so they are now allowed with `repo-s3-uri-style=path`, which most self-hosted S3 services use. 

- Require TLS >= 1.2 unless verification is disabled. TLS 1.0 and 1.1 have been deprecated since 2021. Verification is always enabled for connections between pgBackRest hosts. When verification is disabled for an object store with `repo-storage-verify-tls`, e.g. for a self-signed certificate, every protocol version is allowed. 

- Dynamically size S3/GCS/Azure chunks for large uploads. The number of chunks in an upload is limited, so with the default `repo-storage-upload-chunk-size` the largest file that could be uploaded was 50GiB to S3, 40GiB to GCS, and 200GiB to Azure. The chunk size now grows during an upload, so files up to 5TiB can be uploaded to S3 and GCS and up to 45TiB to Azure. 

- Optimize S3/GCS/Azure chunk size for small files. The whole chunk buffer was allocated when a file was opened, although many files are smaller than a chunk. The buffer now grows as data arrives, which saves memory when small files are uploaded. 

- Remove support for PostgreSQL `9.5`. PostgreSQL 9.5 is no longer supported, per the policy of supporting five end-of-life versions of PostgreSQL. 

- Improve logging of default for options with an unresolved dependency. An option set in the configuration file was logged at the start of a command when its dependency was not resolved, although its default value was used. The option is no longer logged in this case. 

### Core Development

- Simplify the versioned PostgreSQL types. 

- Use get_option() for tasks supported by the new meson version. 

- Simplify the option definitions in config.yaml. 

- Use JsonRead for all info JSON parsing. 

- Refactor StringId and option parsing. 

- Fix logging, formatting, and comments. 

### Documentation Improvements

- Remove explicit `max_wal_senders`/`wal_level` configuration from user guide. `max_wal_senders` and `wal_level` have defaulted to the values the user guide requires since PostgreSQL 10. 

- Clarify that bundling is useful for filesystems with large block sizes. Bundling saves space on filesystems with large block sizes, where each small file takes a whole block. 

### Documentation Development

- Improve the documentation build. 

- Improve wording in the user guide. 

### Test Development

- Fix WAL segment numbering in command/expire unit test. 

- CI updates. 

## v2.57.0 — Suppress Repository Symlinks

*Released: 2025-10-18*

### Core Bug Fixes

- Unnest HTTP/TLS/socket timeouts. A failed socket connection was also retried by the TLS and HTTP layers, so with the default `io-timeout` of 60 seconds a connection took nine minutes to time out. Each layer now retries only its own failures. 

- Fix possible segfault in page checksum error message. The error message for invalid page checksums used a string that was out of scope, which could log garbage or crash. This was most likely with pg_tde, since every encrypted file fails the page checksum. 

- Fix possible segfault in backup resume messages. The message that reports why a backup cannot be resumed used a string that was out of scope, which could log garbage or crash. 

### Core Features

- Add `repo-symlink` option to suppress creation of repository symlinks. Some filesystems that are otherwise Posix-compatible do not support symlinks. Set `repo-symlink=n` to keep the `latest` and tablespace symlinks from being created in the repository. 

### Core Improvements

- Add HTTP retries for 408 and 429 errors. HTTP 408 (Request Timeout) and 429 (Too Many Requests) errors are now retried. 429 errors are common on Cloudflare R2. 

### Core Development

- Finalize catalog number for PostgreSQL 18 release. 

- Remove unused code and fix comments.

## v2.35 — Binary Protocol

*Released: 2021-08-23*

## v0.10 — Backup and Archiving are Functional

*Released: 2014-03-05*

### Core Features

- No restore functionality, but the backup directories are consistent PostgreSQL data directories. You'll need to either uncompress the files or turn off compression in the backup. Uncompressed backups on a ZFS (or similar) filesystem are a good option because backups can be restored locally via a snapshot to create logical backups or do spot data recovery. 

- Archiving is single-threaded. This has not posed an issue on our multi-terabyte databases with heavy write volume. Recommend a large WAL volume or to use the async option with a large volume nearby. 

- Backups are multi-threaded, but the `Net::OpenSSH` library does not appear to be 100% thread-safe so it will very occasionally lock up on a thread. There is an overall process timeout that resolves this issue by killing the process. Yes, very ugly. 

- Checksums are lost on any resumed backup. Only the final backup will record checksum on multiple resumes. Checksums from previous backups are correctly recorded and a full backup will reset everything. 

- The `backup.manifest` is being written as `Storable` because `Config::IniFile` does not seem to handle large files well. Would definitely like to save these as human-readable text. 

### Documentation Features

- Absolutely no documentation (outside the code). Well, excepting these release notes.
